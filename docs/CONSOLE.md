# rscross Web 控制台：功能清单与页面结构

> 参考对象：**gostc-open**（`SianHH/gostc-open`）的界面与交互风格。
> 明确边界：**仅参考前端布局、信息架构与使用流程**；
> 传输实现、配置模型、鉴权与数据面全部是 rscross 自己的，未复用其任何代码或协议。
>
> 同一套 UI 服务两种部署形态：**独立控制台**（多节点汇聚）与**内嵌控制台**（单机自用）。
> UI 会根据 `/api/v1/health` 返回的 `embedded` 字段切换提示文案，但页面结构完全一致。
>
> 默认端口刻意分开：**独立中央控制台 7700**，**内嵌控制台 7800**。
> 同一台机器可以先内嵌自测、再起中央控制台汇聚多节点，互不抢占。

## 2. 页面结构

### 2.1 信息架构

```
登录页  #/login
  └─ 登录成功 → #/dashboard

主框架（左侧固定导航 + 顶部栏 + 内容区）
├── 总览
│   └── #/dashboard        仪表盘
├── 资源
│   ├── #/nodes            服务端节点
│   ├── #/clients          客户端管理
│   ├── #/tunnels          隧道管理（域名解析 / 端口转发 / 私有隧道 / P2P 隧道）
│   └── #/logs             日志
└── 系统
    └── #/settings         配置（含审计记录）
```

hash 路由：服务端只需把未匹配的非 `/api/*` 路径回落到 `index.html`，刷新任意页面都不会 404。
`/api/*` 的未匹配路径返回 **JSON 404**，绝不被 SPA 吞掉（否则前端会把「接口写错了」
误显示成「页面白屏」）。

- 侧边栏固定 220px、深色（`#1e2430`），当前项高亮主色 `#2f6df6`。
- 侧边栏底部显示版本与**控制台形态**（内嵌 / 独立）——这是最容易被忽略、又最能解释
  「为什么节点列表里只有一行」的信息。
- 响应式：≤1080px 四列降两列；≤760px 隐藏侧边栏。

### 2.3 两种形态下的操作流程

#### 方式 B：单机自用（内嵌控制台）

```
① 公网机器：./rscross-server --embedded --config rscross-server.toml
   → 进程内同时跑数据面 + 控制台；自动注册「本机节点」
② 浏览器打开 http://<公网IP>:7800 → 登录（首次密码在标准错误输出）
③ 「客户端管理」→ 签发接入令牌（节点只有一个，自动选中）→ 复制命令
④ 内网机器执行：./rscross-client --console http://<公网IP>:7800 --enroll-token rse_xxx
⑤ 「隧道管理」→ 选「域名解析」→ 填本地地址与公网域名 → ≤15 秒自动下发到客户端
```

「服务端节点」页此时只显示一行本机节点，「添加节点」按钮禁用并给出说明 ——
避免用户以为少了什么功能。

#### 方式 A：多节点汇聚（独立控制台）

```
① 控制台机器：./rscross-console --config rscross-console.toml
② 浏览器打开 http://<控制台IP>:7700（中央控制台默认端口）
③ 「服务端节点」→ 添加节点 → 复制命令
④ 公网机器执行：./rscross-server --managed --console http://<控制台IP>:7700 \
                  --name hk-1 --enroll-token rsn_xxx
   → 节点出现在列表并转为「在线」，同时上报 EndpointId 与隧道端口
⑤ 「客户端管理」→ 签发接入令牌（选择归属节点）→ 复制命令
⑥ 内网机器执行：./rscross-client --console http://<控制台IP>:7700 --enroll-token rse_xxx
⑦ 「隧道管理」→ 选分类 → 新建（选中归属该节点的客户端）
```

**关键交互约定**：客户端命令里**不含任何节点地址**。归属由令牌决定，
之后还能在客户端列表里改派 —— 因此「把客户端迁到另一台节点」不需要动客户端机器上的任何文件。

### 2.4 各页面的组件构成

#### `#/dashboard` 仪表盘
| 区块 | 内容 |
|---|---|
| 统计卡 ×4 | 服务端节点（在线/总数）、客户端（在线/总数）、隧道（启用/总数）、24h 流量（含出入拆分） |
| 流量趋势图 | 原生 SVG 折线（入向实线主色 / 出向虚线绿色）+ 渐变面积；峰值标注 |
| 数据面概况 | 24h 连接数、直连流量与占比、中继流量、控制台形态徽章 + 一句解释 |
| 快速上手 | 按当前形态生成的三步指引 |

#### `#/nodes` 服务端节点
| 区块 | 内容 |
|---|---|
| 表格 | 名称 / 状态徽章 / 对外主机（`public_host` 优先，其次观测到的出口 IP）/ 隧道端口 / 平台 / 版本 / EndpointId（截断 + hover 全量）/ 最近心跳相对时间 / 行操作 |
| 添加节点弹窗 | 节点名 + 对外主机（留空则用控制台观测到的出口 IP）→ 就地展示令牌与可复制命令，提示「令牌只显示这一次」 |
| 行操作 | 「轮换令牌」（二次确认，展示新命令并说明旧令牌立即失效）；「禁用↔启用」；「删除」（二次确认，说明其下客户端会解除归属但保留） |
| 形态说明卡 | 内嵌形态：说明本机节点由服务端进程自动注册；独立形态：说明节点命令的作用 |

#### `#/clients` 客户端管理
| 区块 | 内容 |
|---|---|
| 表格 | 名称 / 状态徽章 / **归属节点** / 出口 IP / 平台 / 版本 / 最近心跳 / 隧道数 / 行操作 |
| 签发弹窗 | 归属节点（只有一个节点时自动选中并只读展示）+ 客户端名 + 令牌有效期 → 展示命令 |
| 行操作 | 禁用/启用；删除（级联删隧道） |

#### `#/tunnels` 隧道管理

按用途分四个 Tab（Tab 上带数量徽章；数据面未接入的分类带「待接入」角标）：

| 分类 | 访问入口 | 关键字段 | 数据面 |
|---|---|---|---|
| **域名解析** | 节点的 HTTP 入口，按 `Host` 路由 | 协议 `http`/`https`、公网域名（留空则由 `ingress.default_domain` 推导）、可选路径前缀 | ✅ 已接入 |
| **端口转发** | 节点监听公网端口（自建 TCP ingress） | 协议 `tcp`/`udp`、公网端口（留空从端口池自动分配） | ✅ 已接入（**仅 TCP**，UDP 待实现） |
| **私有隧道** | 访问端本地监听，**不暴露公网端口** | 协议 `tcp`/`udp`；创建时签发**访问密钥** | ✅ 已接入（访问端 + 节点中继） |
| **P2P 隧道** | 同私有隧道，优先点对点直连 | 协议固定 `tcp`、是否允许中继回退；签发**访问密钥** | ✅ 已接入（直连优先，可配回退） |

| 区块 | 内容 |
|---|---|
| 分类 Tab | 四类切换 + 数量徽章；未接入的分类显示「待接入」角标与说明条 |
| 表格 | 按分类给不同列：域名解析看域名与路径前缀；端口转发看公网端口与限速；私有/P2P 看访问密钥（掩码 + 复制）与中继回退 |
| 新建弹窗 | 按分类给出对应字段与一句形态说明；**数据面未接入时明确提示「配置会保存，但本版本不会建立通道」** |
| 访问密钥弹窗 | 创建 / 轮换后就地展示完整密钥与**可直接执行的访问端命令**（`rscross-client access --console <当前地址> --key ... --listen 127.0.0.1:8080`），一键复制；非 https 环境走 `execCommand` 兜底，否则复制在真机上直接失效 |
| 访问密钥掩码 | 列表里只露前缀与末 4 位（`rsv_······3f21`）：密钥是 20 字符，露太多等于把可用的密钥摆在旁观者眼前，而旁边本来就有「复制」按钮 |
| 行操作 | 私有 / P2P 多一个「轮换密钥」（旧密钥立即失效）；启用/停用；删除 |
| 空态 | 按分类给出引导文案 |

> **为什么单独标注每类的状态**：域名解析的入口是 FerroTunnel 自带的 `http_bind`（按 `Host` 路由），
> 现成可用；其余三类的入口必须由 rscross 自己实现（FerroTunnel 的服务端只提供控制面 `bind`
> 与 HTTP 入口，给不了任意端口监听）。**「配置能保存」不等于「流量能转发」** ——
> 所以像「端口转发的 UDP 入口还没做」这种话，宁可写在界面上，也不要让用户建完才发现不通。

#### `#/logs` 日志
| 区块 | 内容 |
|---|---|
| 工具栏 | 级别下拉 + 关键字输入（250ms 防抖）+ 暂停/继续 |
| 表格 | 时间 / 级别徽章（ERROR 红·WARN 橙·INFO 绿·其他蓝）/ 来源 `target` / 内容（等宽自动换行） |
| 数据源 | 默认读进程内环形缓冲（`?source=live`），可切 `?source=db` 查历史（需 `log.persist = true`） |

#### `#/settings` 配置
| 区块 | 内容 |
|---|---|
| 配置卡 | 三列表单：控制台名、监听地址、对外地址、心跳间隔、离线阈值、端口池、默认域名、节点上限、客户端上限 |
| 保存 | 整体 PUT；服务端**先校验再落盘再换内存**；失败返回 400 并显示原因 |
| 只读态 | `admin.allow_config_edit = false` 时全部禁用并说明 |
| 审计卡 | 最近 50 条审计记录 |

## 4. 前端技术选择说明

**当前用纯 HTML/CSS/JS（无构建步骤）**，通过 `rust-embed` 编进控制面产物。理由：

1. **交付形态优先。** 需求要求「musl 静态无依赖单一二进制」。引入 Vite/Node 构建后，
   CI 里要多一套 Node 工具链、要处理 `dist/` 流转，而收益只是开发体验 ——
   在功能清单还没稳定之前不值得。
2. **CI 更可信。** 少一条工具链就少一类「本地能跑、CI 挂掉」的差异。
3. **体积与启动**：内嵌资源是编译期常量，无额外运行时、无 fs 扫描。

代价与对策：

- 没有组件化/HMR → 用「`shell()` 返回骨架 + `bindShell()` 绑事件 + 每个页面一个 `renderX()`」
  的约定保持结构清晰；状态集中在单个 `state` 对象（含 `nodes/clients/tunnels` 三份缓存，
  用于在表格里把 id 渲染成名字）。
- 没有类型检查 → 所有渲染路径统一 `esc()`；交互入口只有 `data-*` 属性 + `querySelectorAll` 两种形态。
- **迁移路径**：阶段 5 若需要复杂表格/图表，再切 Vite + Vue/React，
  同时在 CI 的 `build-musl` 之前加一个 `web-build` job 产出 `web/dist`，
  让 `rust-embed` 指向它。这条路径不影响「单一文件」性质。
