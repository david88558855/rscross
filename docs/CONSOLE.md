# rscross Web 控制台：功能清单与页面结构

> 参考对象：**gostc-open**（`SianHH/gostc-open`）的界面与交互风格。
> 明确边界：**仅参考前端布局、信息架构与使用流程**；
> 传输实现、配置模型、鉴权与数据面全部是 rscross 自己的，未复用其任何代码或协议。

## 2. 页面结构

### 2.1 信息架构

```
登录页  #/login
  └─ 登录成功 → 跳转 #/dashboard

主框架（左侧固定导航 + 顶部栏 + 内容区）
├── 总览
│   └── #/dashboard        仪表盘
├── 资源
│   ├── #/tunnels          隧道列表
│   ├── #/clients          客户端管理
│   └── #/logs             日志
└── 系统
    └── #/settings         配置（含审计记录）
```

路由为 **hash 路由**：服务端只需把未匹配的非 `/api/*` 路径回落到 `index.html`，
刷新任意页面都不会 404。`/api/*` 的未匹配路径返回 **JSON 404**，绝不被 SPA 吞掉
（否则前端会把「接口写错了」误显示成「页面白屏」）。

### 2.2 布局骨架

```
┌────────────┬──────────────────────────────────────────────────────┐
│  RS rscross│  页面标题                              admin  ⟳刷新 退出 │  ← 顶部栏（sticky）
│            ├──────────────────────────────────────────────────────┤
│  总览       │                                                      │
│   ▤ 仪表盘  │   内容区（卡片栅格，最大宽度 1240px 居中）            │
│   ⇄ 隧道列表│                                                      │
│  资源       │   ┌────────┐┌────────┐┌────────┐┌────────┐          │
│   ▣ 客户端 ③│   │ 统计卡 ││ 统计卡 ││ 统计卡 ││ 统计卡 │          │
│   ≡ 日志    │   └────────┘└────────┘└────────┘└────────┘          │
│  系统       │   ┌──────────────────────────────────────┐          │
│   ⚙ 配置    │   │ 图表 / 表格卡片                      │          │
│            │   └──────────────────────────────────────┘          │
│  v0.1.0     │                                                      │
└────────────┴──────────────────────────────────────────────────────┘
```

- 侧边栏固定 220px、深色（`#1e2430`），当前项高亮为主色 `#2f6df6` —— 与 gostc-open 的观感一致。
- 顶部栏 58px 白色描边，右侧固定「用户名 / 刷新 / 退出」三个动作。
- 内容区背景 `#f4f6fa`，主体是白色圆角卡片 + 极浅阴影。
- 响应式：≤1080px 时四列栅格降为两列；≤760px 隐藏侧边栏（移动端以单列为主）。

### 2.3 各页面的组件构成

#### `#/dashboard` 仪表盘
| 区块 | 内容 | 交互 |
|---|---|---|
| 统计卡 ×4 | 客户端（在线/总数）、隧道（启用/总数）、24h 流量（含出入拆分）、24h 连接数 | — |
| 流量趋势图 | 原生 SVG 折线（入向实线主色 / 出向虚线绿色）+ 渐变面积；峰值标注 | 悬停暂不做（阶段 5 换 canvas + tooltip） |
| 数据面路径卡 | 路径策略、直连健康徽章、直连 RTT、24h 直连占比、24h 中继流量 | — |
| Iroh 节点卡 | 启用状态、EndpointId（等宽字体）、一句解释文案 | — |

#### `#/tunnels` 隧道列表
| 区块 | 内容 |
|---|---|
| 工具栏 | 标题带计数 + 右侧「新建隧道」主按钮 |
| 表格 | 名称 / 协议徽章 / 本地地址 / 公网入口（端口或 Host）/ 所属客户端 / 状态徽章 / 限速 / 行操作 |
| 行操作 | 「启用↔停用」即时生效（PATCH）；「删除」二次确认 |
| 新建弹窗 | 所属客户端 → 名称 → 协议 → 本地地址 →（按协议）Host 或 公网端口 → 限速。**协议切换时动态显隐字段**，避免让用户填无意义的项 |
| 空态 | 「还没有隧道。先添加客户端，再为它创建隧道。」 |

#### `#/clients` 客户端管理
| 区块 | 内容 |
|---|---|
| 表格 | 名称 / 状态徽章（在线·待接入·离线·已禁用）/ 出口 IP / 平台 / 版本 / EndpointId（截断 + hover 全量）/ 最近心跳（相对时间）/ 隧道数 / 行操作 |
| 添加客户端弹窗 | 节点名（可空）+ 令牌有效期 → 签发后**就地展示可复制的一行命令**（含服务端地址、隧道地址、节点名、令牌），并提示「令牌仅显示这一次」 |
| 行操作 | 禁用/启用（`disabled=true` 会让 Agent 的所有 API 立即 403）；删除（级联删隧道） |

> 交互流程刻意做成 gostc-open 那种「**面板签发 → 复制命令 → 目标机器粘贴执行**」的三步式，
> 而不是让用户在客户端手写配置文件。

#### `#/logs` 日志
| 区块 | 内容 |
|---|---|
| 工具栏 | 级别下拉 + 关键字输入（250ms 防抖）+ 暂停/继续（暂停时停止轮询，便于复制） |
| 表格 | 时间 / 级别徽章（ERROR 红·WARN 橙·INFO 绿·其他蓝）/ 来源 `target` / 内容（等宽字体自动换行） |
| 数据源 | 默认读进程内环形缓冲（`?source=live`），可切 `?source=db` 查历史（需 `log.persist = true`） |

#### `#/settings` 配置
| 区块 | 内容 |
|---|---|
| 配置卡 | 三列表单：节点名、三个监听地址、对外地址、心跳间隔、离线阈值、端口池、默认域名、隧道 token、路径策略、Relay 模式、自建 Relay 列表 |
| 保存 | 整体 PUT；服务端**先校验再落盘再换内存**；校验失败返回 400 并显示原因 |
| 只读态 | `admin.allow_config_edit = false` 时全部禁用并给出说明 |
| 审计卡 | 最近 50 条审计记录（时间 / 动作 / 对象 / 来源 IP） |

## 4. 前端技术选择说明

**当前用纯 HTML/CSS/JS（无构建步骤）**，通过 `rust-embed` 编进服务端二进制。理由：

1. **交付形态优先。** 需求要求「服务端 = musl 静态无依赖单一二进制」。
   引入 Vite/Node 构建后，CI 里要多一套 Node 工具链、要处理 `dist/` 的产物流转，
   而收益只是开发体验 —— 在功能清单还没稳定之前不值得。
2. **CI 更可信。** 少一条工具链就少一类「本地能跑、CI 挂掉」的差异。
3. **体积与启动**：内嵌资源是编译期常量，无额外运行时、无 fs 扫描。

代价与对策：
- 没有组件化/HMR → 用「`shell()` 返回骨架 + `bindShell()` 绑事件 + 每个页面一个 `renderX()`」
  的约定保持结构清晰；状态集中在单个 `state` 对象。
- 没有类型检查 → 所有渲染路径统一 `esc()`；交互入口只有 `data-*` 属性 + `querySelectorAll` 两种形态。
- **迁移路径**：阶段 5 若需要复杂表格/图表，再切到 Vite + Vue/React，
  同时把 CI 的 `build-musl` job 前置一个 `web-build` job，产物落到 `web/dist` 后
  再让 `rust-embed` 指向它。这条路径不影响服务端二进制的「单一文件」性质。
